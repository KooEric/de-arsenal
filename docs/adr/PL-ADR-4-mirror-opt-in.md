# PL-ADR-4 — 삭제 전송은 mirror 모드와 비율 상한 뒤에 둔다

- 상태: 승인 (2026-11-18)
- 관련: `packages/pilum/`, [계획](../plans/2026-11-17-pilum-aquila-plan.md)

## 맥락

삭제 요청은 되돌릴 수 없다. 그리고 비어 있거나 경로가 틀린 소스는 "모든 레코드가 사라졌다"와
구분되지 않는다.

## 결정

- 기본 모드는 `upsert`다. 삭제는 `mode: mirror`와 `destination.delete`를 둘 다 써야만 나간다.
- mirror 실행이 원장의 `safety.max_delete_fraction`(기본 50%)을 넘게 지우려 하면 아무것도
  보내기 전에 거부한다. `--confirm-deletes`로만 해제한다.
- 삭제 URL 템플릿은 키 컬럼만 쓸 수 있다. 사라진 레코드의 나머지 값은 알 수 없기 때문이다.
- 삭제에 대한 404는 성공으로 본다.

## 결과

계획의 "mirror는 실행마다 확인"보다 약하다. 스케줄 실행에서 매번 플래그를 붙이게 되면 확인이
의미를 잃으므로, 평소의 소량 삭제는 통과시키고 대량 삭제만 막는다.
