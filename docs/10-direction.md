# 10. 방향성 — 데이터의 Canva, 당신의 AI가 운전한다

> 이 문서는 v0.3.0 이후 프로젝트의 **포지션 전환**을 선언하고, 그 위에서 무엇을
> 어떤 순서로 만들지 정한다. [00-overview.md](00-overview.md)의 제품 철학과
> 설계 원칙은 그대로 유지된다. 바뀌는 것은 **누구를 위해, 무엇과 비교해,
> 어떤 인터페이스로** 존재하느냐다.

## 한 줄 선언

**가입도 과금도 없는 데이터 플랫폼. 이미 있는 노트북과 이미 쓰는 AI로 굴린다.**

- 도구는 무료다. 계정 없음, 미터링 없음, 텔레메트리 없음. `pip install` 하나.
- 컴퓨트는 사용자 노트북이다. 단일 노드 벡터화가 수백 GB까지 덮는다는 것을 벤치마크로 증명한다.
- AI는 사용자가 이미 쓰는 것이다. Claude Code, Cursor, Codex, 또는 로컬 모델. 추가 비용 0.

## 왜 지금 이 포지션인가

### 데이터에는 왜 무료 도구가 없는가

영상·마케팅·디자인에는 무료 툴이 넘친다. 사용자 한 명당 비용이 0에 가깝기 때문이다. Canva는 브라우저에서, CapCut은 폰에서 돈다. 데이터 플랫폼은 다르다. Snowflake와 Databricks는 **그들의 서버에서 내 데이터를 처리**하므로 컴퓨트와 스토리지가 그들의 비용이고, 크레딧과 DBU로 과금할 수밖에 없다. 무료 티어는 체험 후 전환 장치이며, 데이터가 쌓일수록 나가기 어렵고 청구서는 커진다.

데이터에 무료가 없는 것은 인색해서가 아니라 **아키텍처 때문**이다. 무료가 되려면 컴퓨트가 사용자 쪽에 있어야 한다. DE Arsenal은 처음부터 그렇게 설계됐다. 서버 없음, in-process DuckDB, SQLite 상태, 오픈 포맷 단일 복사본. [07-cost-efficiency.md](07-cost-efficiency.md)가 "비용은 철학의 구조적 결과"라고 적은 그 문장이 이 포지션의 근거다. 나중에 붙인 마케팅이 아니라 처음부터 있던 사실이다.

### 데이터에는 왜 AI 도구가 없는가

코드에는 Claude Code가, 디자인에는 Figma와 Canva의 AI가 있다. 데이터에도 Databricks Assistant, Snowflake Cortex, dbt Copilot, 각종 text-to-SQL이 있다. 그런데 전부 두 가지 한계를 가진다.

1. **플랫폼 안에 갇혀 있다.** 그 플랫폼을 사야 쓴다. 무료가 아니다.
2. **SQL 작성까지만 한다.** 수집, 재개, 검증, 드리프트 대응, 백필 같은 **운영**을 에이전트가 수행하는 도구는 없다.

비어 있는 자리는 "데이터용 AI 툴"이 아니라 **"Claude Code가 코드에 한 일을 데이터 파이프라인에"** 다. 에이전트가 파이프라인을 만들고, 돌리고, 깨지면 고치는 운영자가 되는 것. 그 운영자가 붙잡을 수 있는 도구가 필요하다.

### 왜 이 프로젝트가 그 자리에 맞는가

에이전트가 도구를 잘 다루려면 도구가 **결정적이고, 들여다볼 수 있고, 실패해도 다시 시도해도 안전**해야 한다. DE Arsenal은 이 조건을 설계상 이미 갖고 있다.

| 에이전트에게 필요한 것 | Arsenal이 이미 가진 것 |
|---|---|
| 정확하게 생성할 수 있는 입력 | 선언형 YAML. LLM은 Airflow DAG 코드보다 YAML을 훨씬 정확하게 쓴다. JSON Schema(`schemas/`)도 있다 |
| 실행 전 계획 검증 | `gladius compile` — 실행될 정확한 SQL을 보여준다 |
| 안전한 재시도 | 멱등 재실행이 기본값. "일단 다시 돌려보기"가 중복을 만들지 않는다 |
| 상태 조회 | SQLite StateStore, DLQ, lineage edge. 무엇이 어디서 왜 실패했는지 남아 있다 |
| 행동 판단 근거 | `FatalError` / `RetryableError` / `AuthExpiredError` 분류. 재시도할지 사람에게 물을지 결정할 수 있다 |
| 컨텍스트 문서 | 스키마 문서가 코드에서 생성된다(`scripts/gen_schema_docs.py`) |

제품 철학 네 번째 "누구나 쉽게"에 한 줄이 붙는다. **에이전트도 쉽게.**

## 포지션 전환 — Databricks 미니에서 데이터의 Canva로

지금까지의 프레임은 "Databricks 제품군의 저비용 고효율 미니 버전"이었다. 이 프레임은 정확하지만 반론을 부른다. "그럼 TB급은?" Canva는 Photoshop을 이기지 않았다. **Photoshop을 평생 살 일 없는 사람을 데려갔다.**

DE Arsenal의 사용자는 Databricks를 대체하려는 회사가 아니라, **Databricks가 애초에 상대하지 않는 사람들**이다.

| 대상 | 지금까지의 현실 | Arsenal 이후 |
|---|---|---|
| 1인 분석가 | 엔지니어에게 요청하고 기다린다 | AI에게 말하면 파이프라인이 생긴다 |
| 초기 스타트업 | 데이터 인프라는 "나중에" | 첫날부터 노트북 하나로 |
| 학생·연구자 | 무료 티어 만료와 청구서 걱정 | 과금 자체가 없다 |
| 데이터를 직접 만지고 싶은 마케터·기획자 | 도구가 비싸고 어렵다는 게 상식 | 가입 없이 5분 |
| 사이드 프로젝트 | 클라우드 요금 때문에 포기 | 0원으로 끝까지 |

이들에게 "데이터 도구는 비싸고 어렵다"는 상식이라, **무료 자체가 메시지**가 된다.

[00-overview.md](00-overview.md)의 Databricks 대응표는 **내부 설계 지도**로 남긴다. 어떤 문제를 어떤 구조로 더 싸게 푸는지의 참고다. 사용자를 향한 문장에서는 더 이상 Databricks를 기준점으로 쓰지 않는다.

## "무료"의 정직한 정의

"무료 AI"라고 말하면 곧바로 "LLM 호출 비용은 누가 내느냐"는 질문이 온다. 답을 먼저 적는다. 이 프로젝트의 "정직한 한계선" 문화([08-limits.md](08-limits.md))는 여기서도 같다.

| 항목 | 누가 내는가 | 비고 |
|---|---|---|
| Arsenal 도구 자체 | **아무도 안 낸다** | Apache-2.0. 계정·미터링·텔레메트리 없음. 이 약속은 영구적이다 |
| 컴퓨트 | 사용자의 노트북 | 이미 갖고 있는 것. 단일 노드 envelope는 [08-limits.md](08-limits.md) 참조 |
| 로컬 스토리지 | 사용자의 디스크 | Parquet 오픈 포맷. 반출 비용 0 |
| 클라우드 스토리지(S3/GCS sink) | 사용자 | 선택 사항. 우리가 마진을 붙이지 않는다 |
| LLM 토큰 | 사용자 | 이미 구독 중인 Claude Code·Cursor 등이면 추가 비용 0. 로컬 모델이면 0 |
| 노트북을 넘는 규모(Ballista) | 사용자 | P2. 그때부터 사용자가 선택적으로 지불한다 |

**코어는 영원히 무료다.** 나중에 돈을 받는다면 실제로 비용이 발생하는 것, 예를 들어 호스팅된 스케줄러나 관리형 클라우드 실행만이 대상이다. 지금 이 문장을 적어두는 이유는 "무료라더니"라는 배신감을 사전에 막기 위해서다.

## 미래 — 2027년의 하루

방향성이 실현됐을 때 사용자의 하루가 어떻게 생겼는지를 먼저 그린다. 아래 시나리오가 이 문서의 모든 작업 항목의 완료 기준이다.

### 시나리오 1 — 마케터의 첫 파이프라인 (5분, 0원)

> "우리 쇼핑몰 주문 API에서 최근 30일 주문을 받아서 일별 매출 테이블 만들어줘."

Claude Code를 연다. 에이전트가 `arsenal profile`로 API 응답 샘플을 보고, `collect.yaml`과 `transform.yaml`을 쓰고, `arsenal plan`으로 실행될 SQL과 예상 unit 수를 보여준다. 사용자가 승인하면 `arsenal run`. 3분 뒤 `./data/daily_sales/*.parquet`. 가입한 서비스 없음, 청구서 없음.

### 시나리오 2 — 새벽 3시, 아무도 깨지 않는다

612페이지에서 끊겼다. 아침에 에이전트가 `arsenal doctor --json`을 읽는다. 원인은 `RetryableError`(네트워크), 다음 행동은 "재실행". 에이전트가 `arsenal run`을 다시 돌리고 613페이지부터 이어받는다. 재실행 리포트를 사용자에게 한 줄로 보고한다. 사람은 커피를 마시고 있었다.

### 시나리오 3 — 소스가 컬럼을 바꿨다

`schema_drift: block`이 unit을 막았다. 에이전트가 drift 리포트를 읽고 "`user_id`가 `int`에서 `string`으로 바뀜"을 확인한다. `transform.yaml`에 `cast` 한 줄을 추가하는 diff를 제안한다. 사용자가 승인하면 적용 후 재실행. contract도 함께 갱신된다.

### 시나리오 4 — 로직을 고쳤으니 과거를 다시 계산해야 한다

> "지난 1년치를 새 로직으로 다시 계산해."

에이전트가 `onager backfill --dry-run`으로 대상 unit 수, 예상 시간, 디스크 사용량을 보여준다. 격리된 workspace에서 실행하고, 결과를 샘플 쿼리로 검증한 뒤 `promote`를 제안한다. 운영 데이터는 승인 전까지 건드리지 않는다.

### 시나리오 5 — 데이터가 궁금한 사람

> "지난주 대비 어느 카테고리가 가장 많이 빠졌어?"

에이전트가 `arsenal profile`로 컬럼을 확인하고 `arsenal query --format jsonl`로 답을 뽑는다. 파이프라인을 만드는 사람과 데이터를 묻는 사람이 같은 도구를 쓴다.

### 시나리오 6 — 노트북을 닫아도 돌게

> "이거 매일 새벽 2시에 돌게 해줘. 우리 AWS 계정 있어."

에이전트가 Arsenal 스킬과 AWS 스킬을 함께 연다. `arsenal deploy manifest --json`으로 실행 명령, 필요한 비밀값 이름, 상태 경로, 예상 실행 시간을 읽는다. AWS 스킬로 Lambda 컨테이너와 EventBridge 스케줄을 만들고, 상태 경로를 S3로 바꾼다. 첫 실행을 확인하고 사용자에게 보고한다. 우리는 아무것도 호스팅하지 않았다. 청구서는 사용자가 이미 받고 있던 AWS 것 하나다.

**공통점:** 모든 시나리오에서 에이전트는 **실행 전에 계획을 보여주고 승인을 받는다.** 그리고 모든 시나리오에서 사용자는 아무 서비스에도 가입하지 않았다.

## 새 무기 — Augur (AI 층)

로마 군단에서 Augur는 징조를 읽고 지휘관에게 조언하는 자였다. 직접 싸우지 않는다. AI 층의 역할이 정확히 그것이다.

| 무기 | 담당 영역 | 우선순위 |
|---|---|---|
| **Augur** | 에이전트 인터페이스 — 스킬, MCP 서버, 플레이북, 벤치마크 | **P1 (최우선)** |

### Augur의 설계 원칙

1. **코어는 LLM을 모른다.** 설계 원칙 1 "엔진은 빌린다"에서 LLM도 빌리는 엔진이다. Pugio·Gladius·Scutum 등 기존 패키지에 LLM 의존성이 들어가지 않는다. Augur는 별도 패키지다.
2. **똑똑함은 도구 쪽에 둔다.** 무료 포지션을 밀면 로컬 모델이나 값싼 모델을 쓰는 사용자가 생긴다. 그 모델들은 YAML과 SQL을 자주 틀린다. 스키마 검증, 컴파일 미리보기, 실패 진단, 다음 행동 제안을 **도구가 결정적으로** 해주면 약한 모델도 완주한다. "모델이 멍청해도 되는 도구"가 무료 포지션의 기술적 근거다.
3. **모델 중립.** Claude Code, Cursor, Codex, Ollama 어디서든 같은 스킬과 MCP 서버가 동작한다. 특정 벤더에 묶이면 무료 약속이 깨진다.
4. **서비스가 아니라 도구로 남는다.** 웹 앱을 띄우는 순간 호스팅 비용이 생긴다. 사용자가 이미 있는 곳, 즉 Claude Code 플러그인·Cursor·MCP 레지스트리에 들어간다.
5. **에이전트 생성 스펙은 자동 실행하지 않는다.** 아래 신뢰 경계 참조.
6. **다른 스킬과 조합된다.** 배포·클라우드·알림은 우리가 만들지 않는다. AWS 스킬, Cloudflare 스킬이 그 일을 하고, 우리는 그들이 붙잡을 수 있는 계약을 내놓는다. 아래 "조합" 참조.

### 신뢰 경계 — 반드시 먼저 푼다

[08-limits.md](08-limits.md)는 "transform.yaml을 쓰는 사람은 SQL을 실행하는 사람과 같다"고 적었다. 서브쿼리로 로컬 파일을 읽을 수 있다. **스펙 작성자가 LLM이 되는 순간 이 전제가 깨진다.** 따라서 Augur의 첫 작업은 기능이 아니라 방어다.

- **경로 허용 목록.** 스펙이 읽고 쓸 수 있는 경로를 프로젝트 디렉터리로 제한하는 옵션. 에이전트 모드에서는 기본 켜짐.
- **plan → approve → run.** 에이전트가 만든 스펙은 `arsenal plan`으로 컴파일된 SQL과 영향 범위를 보여준 뒤 사람이 승인해야 실행된다.
- **위험 표현식 경고.** `read_csv`, `read_parquet` 같은 파일 읽기 함수가 표현식 안에 나타나면 plan 단계에서 경고한다. 막지는 않는다. 막으면 탈출구가 죽는다.

## 조합 — 우리 스킬은 남의 스킬 옆에 놓인다

Arsenal은 배포 도구를 만들지 않는다. 사용자는 이미 AWS나 Cloudflare에 돈을 내고 있고, 그 클라우드에는 이미 스킬과 MCP가 있다. 에이전트는 두 스킬을 동시에 읽는다. **AWS 스킬은 AWS를 알고, Arsenal 스킬은 데이터 파이프라인을 안다.** 에이전트가 둘을 엮는다.

> "이 파이프라인을 매일 새벽 2시에 돌게 해줘."

에이전트는 Arsenal 스킬에서 "무엇을 어떻게 실행해야 하는지"를 읽고, AWS 스킬에서 "Lambda와 EventBridge를 어떻게 만드는지"를 읽는다. 결과는 사용자의 AWS 계정에 생긴 스케줄이다. 우리는 아무것도 호스팅하지 않았고, 청구서는 사용자가 이미 받고 있던 AWS 청구서 하나뿐이다.

이 구도의 장점은 세 가지다.

- **무료 약속이 유지된다.** 우리는 서버를 띄우지 않고 마진을 붙이지 않는다. 사용자가 이미 내는 돈 위에 공짜로 올라탄다.
- **배포 대상이 저절로 늘어난다.** GCP 스킬, Supabase 스킬이 나오면 우리가 아무것도 안 만들어도 그곳에 배포된다.
- **"한 문제 100점"이 지켜진다.** 클라우드 배포는 우리 문제가 아니다. 우리 문제는 "에이전트가 운영할 수 있는 파이프라인"이다.

Canva의 무료 템플릿이 유료 인쇄 서비스와 함께 쓰이는 것과 같은 자리다. 템플릿은 공짜고, 인쇄는 사용자가 고른 곳에 낸다.

### 조합이 되려면 우리가 갖춰야 할 것

다른 스킬이 Arsenal 파이프라인을 "배포 가능한 것"으로 다루려면 계약이 명확해야 한다. 이것이 Augur가 배포 대신 만드는 것이다.

| 계약 | 내용 | 왜 필요한가 |
|---|---|---|
| **배포 매니페스트** | `arsenal deploy manifest --json` — 실행 명령, 필요한 환경 변수(비밀값 이름만), 스케줄 힌트, 상태·출력 경로, 예상 실행 시간·메모리, 컨테이너 이미지 | AWS 스킬이 Lambda로 만들지 Fargate로 만들지 이 객체 하나를 보고 결정한다 |
| **원격 상태** | `state_dir`이 `s3://`, `r2://`를 받는다. 실행 전 내려받고 끝나면 올린다 | 클라우드 컨테이너는 실행마다 사라진다. 상태가 남지 않으면 재개와 멱등이 깨진다 |
| **컨테이너 이미지** | 공식 `de-arsenal` 이미지. 엔트리포인트는 `arsenal run` | 모든 클라우드 스킬이 같은 이미지를 가리킨다 |
| **비밀값 규약** | YAML에는 `${ENV_NAME}`만. 값은 절대 없음 | AWS 스킬이 Secrets Manager에, Cloudflare 스킬이 Workers Secret에 넣을 이름을 안다 |
| **종료 코드와 JSON 리포트** | 0 성공, 1 Fatal, 2 Retryable. stdout 마지막 줄이 실행 리포트 | 스케줄러가 재시도할지 알림을 보낼지 결정한다 |
| **스킬 문서의 "다른 스킬에게" 절** | SKILL.md 안에 "이 파이프라인을 배포하려면 위 매니페스트를 읽어라"는 안내 | 에이전트가 AWS 스킬을 함께 열어야 한다는 것을 안다 |

### 첫 조합 대상

| 대상 | 스토리지 | 왜 먼저인가 |
|---|---|---|
| GitHub Actions | S3 또는 R2 | 스킬 없이도 되는 가장 쉬운 스케줄러. [dogfooding.md](dogfooding.md)가 이미 권한다 |
| AWS (Lambda 컨테이너 + EventBridge) | S3 | 가장 많은 사용자가 이미 돈을 내는 곳. AWS 스킬·MCP가 가장 성숙 |
| Cloudflare (Containers + Cron Trigger) | R2 | R2는 egress 0원이라 "나가는 비용 0" 약속과 가장 잘 맞는다. Workers 단독으로는 Python DuckDB를 못 돌리므로 Containers 성숙도를 본다 |

정직하게 적을 것: 이 표의 "된다"는 우리가 검증한 뒤에만 문서에 남긴다. 조합 플레이북은 각 대상에서 시나리오 2(새벽 3시 복구)가 실제로 완주된 뒤 게시한다.

## 로드맵 — 세 단계

| 단계 | 한 줄 정의 | 코어에 LLM 의존 | 기간(1인 + AI 에이전트) |
|---|---|---|---|
| **L1** 에이전트가 쓸 수 있는 도구 | 사람 대신 에이전트가 CLI를 운전해도 막힘이 없다 | 없음 | 2~3주 |
| **L2** 에이전트 전용 인터페이스 | 에이전트를 1급 사용자로 설계하고, 완주율을 측정한다 | 없음 | 1~2개월 |
| **L3** 자체 AI 기능 | arsenal 자체가 대화형으로 동작한다 | 있음, 교체 가능한 백엔드 | L2 벤치마크 결과가 정당화할 때만 |

### L1 — 에이전트가 쓸 수 있는 도구

목표: Claude Code에 스킬 하나를 얹으면 시나리오 1·2가 **오늘 동작**한다.

| 작업 | 내용 | 완료 기준 |
|---|---|---|
| **REST 증분 워터마크** (선행) | `incremental: { param: updated_after, field: updated_at, window: 1d, lag: 5m }`. 실행마다 마지막 워터마크부터 지금까지를 시간 창 unit으로 낸다. 창은 약간 겹치고 중복은 sink `merge_key`가 흡수 | "매일 새 주문만"이 REST에서 된다. 지금은 offset/page 완료 후 no-op, cursor 소진 후 unit 없음 — 시나리오 1·2·6의 전제 |
| `--json` 전 명령 | `run`, `status`, `dlq list`, `compile`, `profile`, `doctor`, `plan`의 출력을 구조화 | 모든 명령이 `--json`으로 파싱 가능한 단일 객체를 stdout에 낸다. 사람용 출력은 그대로 |
| `arsenal profile <path\|url>` | 컬럼명·타입·null 비율·distinct·샘플 5행. Parquet·CSV·REST 응답 샘플 | 에이전트가 데이터를 보지 않고 transform을 쓰는 일이 없어진다 |
| `arsenal plan` | pugio dry-run(unit 수·재개 지점) + gladius compile + 영향 경로 목록 + 위험 표현식 경고 | 실행 없이 "무엇이 일어날지"를 한 객체로 |
| `arsenal doctor` | 마지막 실행의 실패를 `Fatal/Retryable/AuthExpired` + 원인 + **다음 행동** 으로 진단 | 에이전트 루프가 닫힌다: run → doctor → 행동 → run |
| 경로 허용 목록 | `arsenal.yaml`의 `sandbox.paths` 또는 `--sandbox` | 프로젝트 밖 경로 접근 시 plan 단계에서 FatalError |
| 스킬 | ✅ `skills/` 5종 + `.claude-plugin/` 플러그인·마켓플레이스 매니페스트. 스키마 참조는 `gen_schema_docs.py`가 생성 | Claude Code에서 시나리오 1·2 완주 (외부 사용자 검증은 남음) |
| JSON Schema 게시 | `schemas/*.json`을 패키지에 포함, `arsenal schema pipeline\|transform` 명령 | 에이전트가 실행 전 스펙을 로컬 검증 |
| 원격 상태 | `state_dir: s3://…` / `r2://…`. 실행 전 pull, 종료 시 push, 실패 시에도 push | 클라우드 컨테이너에서 재개·멱등이 유지된다. 조합의 선행 조건 |
| 배포 매니페스트 | `arsenal deploy manifest --json` + 종료 코드 규약 | 다른 스킬이 이 객체만 보고 배포할 수 있다 |

### L2 — 에이전트 전용 인터페이스

목표: 시나리오 3·4·5가 동작하고, **완주율이 숫자로 나온다.**

| 작업 | 내용 | 완료 기준 |
|---|---|---|
| Augur MCP 서버 | `packages/augur`. L1 명령을 MCP tool로 노출. stdio 전송 | Claude Code·Cursor에서 설정 3줄로 연결 |
| 플레이북 6종 | 새 소스 온보딩 / 실패 분류·복구 / 드리프트 대응 / 백필 계획·승격 / 데이터 질문 / **클라우드로 졸업(AWS·Cloudflare 스킬과 조합)** | 각 플레이북이 스킬 문서 + 예제 프로젝트를 가진다 |
| 공식 컨테이너 이미지 | `ghcr.io/kooeric/de-arsenal`, 엔트리포인트 `arsenal run` | 모든 클라우드 스킬이 같은 이미지를 가리킨다 |
| **DE 벤치마크** | 현실적 과제 20~30개. 에이전트가 arsenal로 완주하는지 자동 채점 | `benchmarks/agent/RESULTS.md`에 모델별 완주율. 이 숫자가 "AI for DE"를 분위기가 아니라 측정으로 만든다 |
| Claude Code 플러그인 | 스킬 + MCP를 플러그인으로 묶어 마켓플레이스 등록 | `claude plugin install de-arsenal` |
| 승인 게이트 | plan → approve → run을 MCP 흐름에서 강제 | 에이전트가 승인 없이 run을 호출할 수 없다 |

벤치마크는 Databricks 대응표를 대체하는 **새 기준점**이다. "우리는 몇 점짜리 도구인가"를 그들의 기능표가 아니라 에이전트의 완주율로 답한다.

### L3 — 자체 AI 기능

L2 벤치마크에서 "도구가 아니라 대화가 병목"이라는 증거가 나올 때만 시작한다.

- `arsenal ask "..."` — 스펙 생성·수정을 arsenal 안에서. 모델 백엔드는 설정으로 교체(Anthropic·OpenAI 호환·Ollama).
- contract 자동 추론 — `profile` 결과에서 `DataContract` 초안 생성.
- 분석가 모드 — `query` + `profile` 위에 자연어 질의.

L3에서도 기존 무기들은 LLM을 모른다. 전부 Augur 안에 산다.

## 성공의 정의

| 시점 | 지표 |
|---|---|
| L1 완료 | Claude Code + 스킬로 시나리오 1·2를 외부 사용자 3명이 문서만 보고 완주 |
| L2 완료 | 벤치마크 완주율이 최상위 모델에서 80% 이상, 로컬 7B급 모델에서 50% 이상. 시나리오 6이 AWS 스킬과의 조합으로 외부 사용자 1명 이상에서 완주 |
| 1년 | "무료 데이터 플랫폼"으로 검색했을 때 이 프로젝트가 나온다. 도그푸딩 회고 10건 이상 |

두 번째 줄의 "로컬 모델에서 50%"가 무료 포지션의 진짜 시험이다. 모델이 약해도 도구가 받쳐주는지를 재는 숫자다.

## 바뀌지 않는 것

- 제품 철학 네 가지. 가볍게, 빠르게, 정확하게, 누구나 쉽게.
- 설계 원칙 일곱 가지. 특히 "엔진은 빌린다"와 "각 도구는 독립".
- 한 문제, 최고의 해결책. Augur의 한 문제는 **"에이전트가 운영할 수 있는 파이프라인"** 하나다. 그 밖으로 번지면 백 가지 80점이 된다.
- 정직한 한계선. 무료의 경계도, 에이전트의 한계도 먼저 말한다.
