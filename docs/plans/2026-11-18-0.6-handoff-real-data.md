결과 원문은 [docs/11-real-data-experiments.md](../11-real-data-experiments.md)에 있다.
여기에는 0.6.0을 만들 때 알아야 할 것만 추렸다.

## 2. 0.5.3에서 이미 고친 것 (다시 고치지 말 것)

1. **offset 모드 + 페이지 번호형 `param` → 스펙 검증 에러.**
   `PaginationSpec._offset_mode_not_page_numbered` (`packages/arsenal-core/src/arsenal_core/spec/models.py`).
   `github-issues` 레시피는 `mode: page`.
2. **CSV `NA`가 null로 바뀌던 문제.** `FileSourceSpec.null_values` (기본 `[""]`),
   `packages/pugio/src/pugio/sources/file.py`에서 `ConvertOptions(null_values=...)`.

## 3. 0.6.0 후보: 실데이터로 확인한 한계 2건

둘 다 재현 스펙과 실측 숫자가 있다. Pilum 범위에 넣을지는 0.6.0 세션이 판단한다.
**Pilum과 직접 맞물리는 건 (A)다.**

### (A) 검증 게이트가 단위 전체를 격리한다 → 실데이터에서 적재 0건

- **증거:** NYC 택시 2024 Q1(955만 행, row group 10개)에 `total_amount min 0`,
  `trip_distance 0~200`을 걸었다. 위반은 약 1.2%(음수 금액 115,895건)인데 **10개 단위가 모두 격리되고
  적재 0건**이었다. 실데이터는 어느 덩어리에나 환불 건이 섞여 있다.
- **코드:** `packages/pugio/src/pugio/runner.py` 약 268~300행. `check(result.batch, rules)`가 batch
  전체에 대해 `report.ok`만 판정하고, quarantine이면 batch 전체를 `write_dlq`로 보낸다.
  검증 함수는 `packages/pugio/src/pugio/validate/gate.py`.
- **제안:** `on_violation: split`. 위반 행만 DLQ Parquet으로, 나머지는 sink로 보낸다.
  기존 `block`/`quarantine`/`warn`은 그대로 둔다(기본값 유지 → patch 아닌 minor 기능 추가로 충분).
  - 주의 1: 같은 unit이 "일부 적재 + 일부 DLQ"가 된다. 상태는 `done`으로 두고, 격리 행 수를 따로
    기록해야 `pugio status --cost`와 `dlq list`가 맞다.
  - 주의 2: 행 마스크는 Arrow compute로 벡터화해야 한다. 지금 gate는 위반 개수를 이미 세므로,
    마스크를 반환하게 바꾸면 된다.
- **Pilum과의 관계:** Pilum은 외부로 보내는 첫 무기다. 행 몇 개가 나쁘다고 배치 전체를 안 보내거나,
  반대로 나쁜 행까지 보내면 둘 다 비싸다. Pilum에 발사 전 검증을 붙일 거라면 **행 단위 분리가
  전제 조건**이다.
- **재현:** `experiments/real-data/nyc-taxi/gate.yaml` (`PYTHONPATH=.`로 `nyc_source.py` 사용).

### (B) 스키마 변화 감지가 한 실행 안의 파일 간 차이를 못 본다

- **증거:**
  - 실행 간: NYC 2022-01 → 2024-01은 `schema_drift: block`이 정확히 막았다
    (`added=Airport_fee; removed=airport_fee; changed=DOLocationID,PULocationID,RatecodeID,VendorID,passenger_count,store_and_fwd_flag`).
  - 한 실행 안: 공항 CSV 7개 파일 중 하나만 `continent`가 null 타입이었는데 그대로 통과했다.
    0.5.3에서 고친 `NA` 버그를 놓친 원인이다.
- **코드:** `runner.py` 215, 229~242행. `schema_recorded` 플래그 때문에 run당 첫 non-empty batch만
  `store.last_schema()`와 비교한다. `docs/08-limits.md` 47행에 한계로 문서화돼 있다.
- **제안:** 매 batch를 직전 스냅샷과 비교하고, 바뀌었을 때만 `snapshot_schema`를 기록한다.
  비교는 JSON 문자열 비교라 비용이 작다. `08-limits.md` 47행도 같이 고친다.
- **참고:** Aquila는 Parquet footer를 읽어 같은 변화(`continent: string → null`)를 이미 기록한다.
  수집 게이트와 연결되지 않았을 뿐이다.
- **재현:** `experiments/real-data/airports/airports-gate.yaml`
  (0.5.3에서는 `NA`가 보존되므로, 재현하려면 한 파일의 컬럼 타입을 일부러 바꿔야 한다).

## 5. 릴리스·환경에서 알아 둘 것 (0.5.3에서 겪은 것)

- **Claude 세션은 태그를 push할 수 없다.** `git push origin v0.6.0`이 끊기거나 "Everything up-to-date"만
  내고 원격에 태그가 생기지 않았다. 태그는 사용자가 직접 push하거나, GitHub 웹의 Releases →
  "Draft a new release"에서 새 태그로 Release를 만든다(이 방법도 `release.yml`을 실행시킨다).
- **`release.yml` 수동 실행(workflow_dispatch)은 세션 권한으로 403.** 태그로 시작되는 실행도
  `verify-and-build`를 먼저 통과해야 publish하므로 생략해도 안전장치는 남는다.
- **`ballista-e2e`가 Maven Central 429로 실패할 수 있다.** Docker 빌드 중 Iceberg jar 다운로드가 원인이고
  코드와 무관하다. 0.5.3 PR에서 한 번 실패했고, 새 커밋 push로 다시 돌자 통과했다.
- **0.x 버전 규칙:** 호환되지 않는 동작 변경은 minor. 0.6.0은 Pilum이라 어차피 minor다.
  (A)의 `split`은 새 정책 추가라 기존 동작을 바꾸지 않는다. (B)는 `block` 사용자에게 새로 막히는
  경우가 생기므로 CHANGELOG Upgrade notes에 적어야 한다.
- **pyright를 로컬에서 돌릴 때는** `uv run pyright` 또는 `.venv/bin/pyright --pythonpath .venv/bin/python`.
  venv를 못 찾으면 수천 개의 가짜 에러가 난다.

## 6. Augur (0.6.0 범위 밖이면 무시)

- PR #23에서 `OPENAI_BASE_URL`을 추가했다. Gemini 무료 티어로 평가 가능
  (`OPENAI_BASE_URL=https://generativelanguage.googleapis.com/v1beta/openai`).
- `gemini-3.1-flash-lite` 34/34 정답. 평가 세트가 너무 쉽다는 뜻으로 해석했다.
- `gemini-flash-latest`는 무료 한도가 **하루 20요청**이라 평가를 끝까지 못 돈다.
- API 키는 레포·문서·커밋에 절대 넣지 않는다. `OPENAI_API_KEY` 환경변수나 `augur auth set`으로만 준다.
